# 3. Trang Lịch sử phiên bản

## 3.1. Route

Route chính:

```text
/versions
```

Route chi tiết:

```text
/versions/{version}
```

Ví dụ:

```text
/versions/v2.3.0
/versions/v2.2.0
```

Trang public, không yêu cầu đăng nhập.

Khi truy cập `/versions`, hệ thống mặc định hiển thị version `published` gần nhất.

Nếu version không tồn tại:

```text
404
```

Không fallback âm thầm sang latest.

---

## 3.2. Mục tiêu

Trang Version History dùng để:

- Hiển thị lịch sử thay đổi DrinkFlow.
- Giới thiệu feature mới.
- Hiển thị improvement.
- Hiển thị bug fix.
- Hiển thị security update.
- Cho User chọn version.
- Cho phép bookmark/share trực tiếp version cụ thể.

## 3.8. Laravel Route

```php
Route::get(
    '/versions/{version?}',
    VersionHistoryController::class
)->name('versions');
```

Controller:

- Có `{version}` → load đúng published version.
- Không có `{version}` → load latest published.
- Không tìm thấy → 404.

Các nhóm đề xuất:

```text

🐛 Fixed
🔐 Security
```

Ví dụ:

### New

- Google Authentication bằng email công ty.
- Global User + Room User.
- Multi-room.

### Improved

- Trusted Device Authentication.
- Socket.IO authorization.
- Realtime flow.

### Fixed

- Duplicate Order handling.
- Room data isolation.

### Security

- Chặn cross-room access.
- Không expose credential xuống browser.

## 3.15. Force Refresh

`force_refresh` dùng để đánh dấu version yêu cầu client refresh application.

Dùng khi:

- Asset thay đổi lớn.
- Frontend cache cần reset.
- Có breaking UI change.

Không hard refresh liên tục.

## 3.18. Superadmin Version Management

Superadmin:

- Create.
- Edit.
- Preview.
- Publish.
- Unpublish.
- Archive.

Flow:

```text
Draft
   ↓
Preview
   ↓
Publish
   ↓
Visible to User
```

---

## 3.19. Version Publish Rule

Khi publish:

1. Validate version unique.
2. Validate release date.
3. Validate content.
4. Set `status = published`.
5. Clear cache.
6. Emit event nếu cần.
7. Update current public version nếu là latest.

Optional event:

```text
system.version.published
```
